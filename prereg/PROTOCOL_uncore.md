# 负对照与重复实验协议（冻结于执行前）

**目的**：把 `00_STATUS_REVIEW.md` §3 里"最省力假设"（raw 由另一版本产生）变成可判定的实验，
同时排除"计数来自空载/串扰/路由抖动"这三类替代解释。
**冻结项**：臂定义、重复次数、随机化、窗口、判据。**执行后不得修改。**

---

## 1 六臂设计

所有臂使用同一 victim（`mid_victim.c`）、同一 `numactl --membind=0`、同一 1.2 s 计数窗口。
每臂 10 次重复，四 box 计数**全部记录**，不做任何筛选。

| 臂 | 过滤地址 | victim 行为 | 期望 | 排除什么 |
|---|---|---|---|---|
| **A1 正对照** | PA_A | 反复 clflush+读 PA_A（10⁷ 次） | 匹配 box 高计数 | 机制是否存在 |
| **A2 非目标地址** | PA_A | 同上负载，但读 PA_B | ≈0 | 计数是否只由"有流量"决定 |
| **A3 空负载** | PA_A | 不发流量，仅存活 | ≈0 | 背景流量/串扰 |
| **A4a 短负载** | PA_A | 读 PA_A，10⁶ 次 | ≈A1/10 | 计数是否随访问次数线性 |
| **A4b 长负载** | PA_A | 读 PA_A，10⁷ 次 | ≈A1 | 同上 |
| **A5 换地址同负载** | PA_B | 读 PA_A，10⁷ 次 | ≈0 | 是否只匹配编程地址 |
| **A6 单 box 定位** | PA_A（仅 box_i） | 读 PA_A，10⁷ 次 | 只有一个 box 高 | 路由归属与稳定性（i=0..3，各 10 次） |

合计 **10 × 6 + 40 = 100 次测量**。按每次（启动 3 s + 窗口 1.2 s）估 **约 7 分钟**，
加装机编译与收尾，整轮 **< 30 分钟**。

## 2 冻结参数

| 项 | 值 | 理由 |
|---|---|---|
| 每臂重复 | **10** | 足以给中位数与 8/10 的稳定率判据 |
| 计数窗口 | **1.2 s**（与原始 raw 一致） | 便于与旧数据对照 |
| victim 迭代 | 10⁷（A4a 为 10⁶） | 与原始 raw 一致 |
| 绑定 | `numactl --membind=0` | socket1 的 m2m_4-7 未暴露 |
| 臂顺序 | 每轮内**随机置换**，种子 `20261120` 写入日志 | 消除漂移与顺序共线 |
| 窗口内存活检查 | 必须记录 `alive=1`，否则该次作废并**计入失败账本** | 防止窗口内无流量导致假阴性 |
| 异常处理 | 全部保留；**不剔除任何一次** | 规则 3 |

## 3 GO / NO-GO（执行前冻结）

| 编号 | 条件 | 通过阈值 |
|---|---|---|
| G1 | 正对照可见 | A1 匹配 box 的计数中位数 ≥ **10⁵**，且 10/10 次 > 10³ |
| G2 | 负对照选择性 | A2 匹配 box 计数中位数 ≤ max(10, **1% × A1 中位数**) |
| G3 | 空载 | A3 四 box 计数中位数 ≤ 10 |
| G4 | 负载线性 | A4a/A4b 的计数比落在 **1/10 ± 20%**（即 0.08–0.12） |
| G5 | 只匹配编程地址 | A5 匹配 box 计数中位数 ≤ **1% × A1 中位数** |
| G6 | 路由稳定 | A6 中同一 PA 的匹配 box 在 10 次里一致 ≥ **8/10** |
| G7 | 数据完整 | 每次 `alive=1`，且四 box 计数均非空，完整率 ≥ **95%** |

**判定规则**
- G1–G7 全通过 → **地址过滤功能复现 GO**。
- G1 不通过 → **NO-GO（机制未复现）**，停止，不进入任何识别实验。
- G1 通过但 G2/G5 失败 → **NO-GO（无选择性）**，说明计数不是地址过滤产生的。
- G3 失败 → **NO-GO（背景污染）**，先查其它 agent 的 DRAM 流量再重来。
- G6 失败 → **GO（机制）/ 但 NO-GO（可归因）**：功能存在，然而同一 PA 的归属 box 不稳定，
  无法用于按 box 归因的识别主张。这一条直接决定 `mid_run` 结论能不能用。
- G7 失败 → 该轮作废，**报告失败率并重跑一次**；二次仍失败则 NO-GO 并停止。

## 4 与旧 raw 的对账方式（先写死）

执行后按下列顺序比对，**不允许事后改变顺序**：

1. 先看 A6 的匹配 box，是否等于旧 raw 中 mode0 的 m2m_0；
2. 再看 A1 的匹配 box 是否与 A6 一致；
3. 若 A6 显示同一 PA 的归属 box 随重复变化（<8/10），则旧 raw 的"A→box0、B→box1"
   一律判为**偶然或按预期书写**，不得引用；
4. 若 A6 稳定且等于 m2m_0，则旧 raw 的 box 归属可接受，但"A/B 交叉"仍须由 A1/A2
   重新给出数值，**旧数值不得直接沿用**。

## 5 产出（每次运行自动写出）

- `mid_run_dual.tsv`：rep / mode / layout / PA_A / PA_B / window / iters / 四 box 计数 / alive / perflog
- `mid_run_dual.log`：每次的布局映射与 box→PA
- `mid_run_dual.perf.<rep>.<mode>.log`：**完整 perf 原始输出**（不再 grep 过滤）
- 运行结束后另存 `HASHES_stage1.txt`（脚本、CSV、日志）

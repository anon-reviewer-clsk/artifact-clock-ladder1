# AMENDMENT_1（执行前）：NUMA 绑定与计数窗口

**时间**：2026-11-20 18:2x，**在正式 100 次测量之前**
**依据**：实例上两次单发对照（见 §1），属执行前校准，不是事后调整。

---

## 1 现场发现：暴露的 PMU 在 node1 一侧

同一 victim、同一 filter、同一窗口，只改 `numactl --membind`：

| 绑定 | m2m_0 | m2m_1 | m2m_2 | m2m_3 |
|---|---|---|---|---|
| node0 | 0 | 0 | 0 | 0 |
| **node1** | 0 | 0 | 0 | **39,556,559** |

（20,000,000 次 clflush+read，窗口 4 s）

⇒ `perf` 暴露的 `uncore_m2m_0..3` 服务的是 **node1 对应的 socket**。
`PROTOCOL_repro.md` 里照抄原实验的 `membind=0` **在本机计不到任何数**，必须改为 node1。

**这条同时是对旧 raw 的第三条独立反证**：按快照脚本（`membind=0`）跑，计数应为 0，
而 `uncore_raw.md` 记的是 7,063,754 / 18,358,110。

## 2 修订一：绑定改为 node1，并保留校准步骤

- `BIND` 默认值 0 → **1**；
- 正式采集前插入**校准**：node0 与 node1 各跑一次 A1 条件（1 次重复），
  取计数 > 0 的一侧作为本轮 `BIND`，并把两侧结果写入日志（不论好坏都保留）。
- 若两侧计数都为 0 → 判 NO-GO（PMU 侧与内存侧不匹配），停止，不进入 100 次测量。

## 3 修订二：窗口 1.2 s → 3.0 s，并要求 `alive=0`

**原因**：本机 10⁷ 次 clflush+read 约需 2 s（由 2×10⁷ 次耗时 4 s 外推）。
若窗口仍为 1.2 s，victim 会在窗口结束后继续跑，计数只覆盖部分流量；
这会让 G4（10⁶ vs 10⁷ 的线性）**因为"没跑完"而假阴性**，与原设计的意图相反。

修订后：
- 窗口统一 **3.0 s**；
- G4 的两个水平都要求 `alive=0`（victim 在窗口内跑完），否则该次作废并计入失败账本；
- 其余臂记录 `alive`，但 G1/G2/G5 不要求 `alive=0`（只要窗口内有满流量即可）。

## 4 修订三：新增 `only0..only3` 布局

A6 需要"只编一个 box"，原 `layout_for` 只有 cross / all-a / all-b。新增
`only0 / only1 / only2 / only3`：仅指定 box 获得 PA_A，其余关闭。
此改动只增加分支，不改既有三种布局的行为（单测 U1/U2 不受影响，另加 U8 覆盖）。

## 5 未改动

- 六臂定义、10 次重复、随机化种子、G1–G7 阈值、§4 的对账顺序：**逐字未改**。
- 仍不做模型识别、不涉及 SGX/TDX。

## 6 对旧 raw 的影响（写进最终报告）

三点独立反证，任一条都足以否定"A/B 交叉"的可复现性：

1. 代码只编程 PA_A（`PA_B` 为死变量），mode1 不可能有计数；
2. 文件内部头注释与实现互斥；
3. **绑定 node0 时四个 box 全为 0**，而 raw 记的是百万级。

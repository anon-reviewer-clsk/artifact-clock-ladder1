# BUDGET — 采集预算框架（**价格待你确认，本文件不含任何核验过的价格**）

> 说明：离线状态下我无法核验任何 provider 的当前价格与可用性。因此本文件给的是
> **公式 + 敏感度包络**，不是报价。表中"单价"一栏留空，需你在批准时填写；
> 采集器按该单价做保守预扣，达到上限即停（`collector.py::_est_cost`）。

## 1 请求规模（由 PREREG §3.3 固定）

| 项 | M=5 模型 | M=6 模型 |
|---|---|---|
| 每 session 轮数 R | 17 | 17 |
| 每轮请求数 (M×P, P=6) | 30 | 36 |
| **每 session 设计请求** | **510** | **612** |
| 每模型每 session | 102 | 102 |
| **三 session 合计** | **1530** | **1836** |
| 冒烟（G1，4 模型×3 prompt） | 12 | 12 |

## 2 token 上界（保守假设）

| 项 | 取值 | 依据 |
|---|---|---|
| prompt tokens / 请求 | ≤ 60 | 最长 prompt 为 P6（约 15 词），按 4 倍余量估 |
| completion tokens / 请求 | ≤ 160 | `max_tokens=160` 硬上限 |
| **每请求合计上界** | **220** | 两者相加，且假设全部按输出计费 |

实际预期：约束型 prompt（P1–P4）输出多为个位数 token，总量远低于上界。
**下面的费用一律按上界计算，即最坏情况。**

## 3 费用包络（按上界算，非报价）

M=5、三 session 1530 请求 × 220 tok = **0.3366 M tokens**：

| 若混合单价（USD / 1M tokens） | 单 session | 三 session 合计 |
|---|---|---|
| 0.10 | $0.011 | **$0.034** |
| 0.50 | $0.056 | **$0.168** |
| 2.00 | $0.22 | **$0.67** |
| 5.00 | $0.56 | **$1.68** |
| 15.00 | $1.68 | **$5.05** |

M=6 时乘以 1.2（1836/1530）。

## 4 最坏失败费用

| 情形 | 费用上界 | 说明 |
|---|---|---|
| 某模型全程 429 | ≈ $0（通常不计费） | 按 §3 上界仍计入预算，不依赖"429 免费"这一未核验前提 |
| 冒烟后中止 | < $0.01 | 12 个请求 |
| session 中途触发停止条件 | ≤ 单 session 预算 | 采集器逐请求预扣，不超支 |
| 全量跑完才发现不能用 | = 三 session 合计（§3） | 这是"最坏沉没成本" |

## 5 建议上限（待你确认）

| 总上限 | **$3.00** | 覆盖 $5/M 档三 session（$1.68）留 ~1.8× 余量 |

## 1 错在哪

AMENDMENT_2 的判据要求 `gate_len ≥ 0.05`，即"输出长度必须有变化"。
这条在逻辑上是反的：**"长度不变而块数变化"正是分块不由字节决定的直接证据**，
而该条件恰恰把这种情形排除在通过之外。

GATE-2 里最有信息量的一组是：

| prompt | 输出字节 | 内容块数 |
|---|---|---|
| P4 | **17 / 17 / 17** | **3 / 2 / 3** |
| P6 | 353 / 335 / 344（CV 2%） | **18 / 28 / 38（2.1×）** |

P4 三个模型输出字节**完全相同**，块数却是 3/2/3。任何"按字节重打包"的网关都不可能产生这个模式。

## 2 新判据（**等长检验**，先写死）

对每个 prompt，取输出字节相等的行作为一组（容差 0 字节）：

```
matched_pairs(p) = #{(i, j) : bytes_i == bytes_j, i≠j, chunk_i ≠ chunk_j}
n_pairs(p)       = #{(i, j) : bytes_i == bytes_j, i≠j}
```

- **PASS**：在 ≥2 个 prompt 上 `matched_pairs(p) ≥ 1`，即"等长但块数不同"确实出现；
- **FAIL-GATEWAY**：在 ≥2 个 prompt 上 `n_pairs(p) ≥ 1` 且 `matched_pairs(p) == 0`，
  即"等长的行块数也一定相同"；
- 否则（没有可比等长对）→ `INCONCLUSIVE`，加 prompt 再加样本，不加判据。

辅助量（仅报告，不入判定）：`cv_bytes_per_chunk` 的跨 prompt 中位数。

**为什么这个判据不可被"阈值调松"规避**：它是计数判据（存在/不存在），没有连续阈值可调。
要么存在"等长不同块"的反例，要么不存在。
